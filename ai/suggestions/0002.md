## Detailed Analysis

### 🔴 Still Applicable (High Priority)

#### 1. Feature-Based Package Structure
**Current:** Layer-based structure (`data/`, `pages/`, `components/`, `components/chars/`)  
**Suggested:** `features/food`, `features/home`, `features/settings`, `features/garmin` + `core/`  
**Impact:** High - improves modularity, discoverability, and scaling

#### 2. Repository Layer
**Current:** ViewModels directly inject DAOs (`FoodDao`, `FoodEatenDao`, `SettingsDao`, `GarminCaloriesDao`)  
**Suggested:** `FoodRepository`, `FoodEatenRepository`, `SettingsRepository`, `GarminRepository` in `core/data/`  
**Impact:** High - enables testing, future API integration, decouples UI from data source

#### 3. Hilt Dependency Injection
**Current:** Manual `ViewModelProvider.Factory` in every ViewModel (7+ files)  
**Suggested:** `@HiltViewModel` + `@Inject` constructor injection  
**Impact:** High - eliminates boilerplate, enables proper scoping, standard Android practice

#### 4. Consolidate Navigation Logic
**Current:** `@Serializable` `NavKey` definitions in `NavigationRoot.kt` (lines 23-48)  
**Suggested:** Move to `navigation/` package or respective `features/*/navigation.kt`  
**Impact:** Medium - separates routing from navigation graph definition

#### 5. Cleanup Redundant Files / ViewModels in Wrong Layers
**Current:** 
- `data/food/` contains 4 ViewModels (`AddFoodViewModel`, `AddFoodItemViewModel`, `EditFoodItemViewModel`, `AddFoodMealViewModel`)
- `data/home/` contains `HomeViewModel`
- `data/settings/` contains `SettingsViewModel`
- `components/chars/` contains `MacroChartViewModel` (feature-specific ViewModel in components)

**Issue:** ViewModels in `data/` layer (should be in features); feature-specific ViewModel in `components/`  
**Impact:** Medium - architectural consistency

#### 6. Centralize UI Components
**Current `components/` directory mix:**
| Generic (✅ Keep) | Feature-Specific (❌ Move) |
|-------------------|---------------------------|
| `FoodImage.kt` | `DateBar.kt` (Home) |
| `MacroList.kt` | `DateNavigator.kt` (Home) |
| `SingleFood.kt` | `MacroChart.kt` (Home/Charts) |
| `Macros.kt` | `MacroChartViewModel.kt` (Home/Charts) |
| `FoodList.kt` | |

**Impact:** Medium - `components/` should only contain truly reusable UI

#### 7. Modernize Time Handling
**Current `util/Time.kt`:** Mix of modern and legacy APIs
```kotlin
// Modern ✅
import java.time.Instant
import java.time.temporal.ChronoUnit
import java.time.Clock

// Legacy ❌ (minSdk 36 supports java.time fully)
import java.util.Date
import java.text.SimpleDateFormat
import java.util.Locale
```
**Impact:** Low - code works, but inconsistent; minSdk 36 = full java.time support

   - Move `DateBar`, `DateNavigator`, `MacroChart`, `MacroChartViewModel` from `components/`
3. **Settings Feature** (`features/settings/`)

4. **Garmin Feature** (`features/garmin/`)

### Phase 4: Finalization - LOW PRIORITY

2. **Clean Up** - Remove empty `data/`, `pages/`, `components/chars/`, old `util/`
