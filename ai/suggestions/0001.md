# Refactoring Suggestions for CaloryTracker

Based on the current project structure and code analysis, here are the recommendations for refactoring:

## 1. Feature-Based Package Structure
Transition from a layer-based or mixed structure to a **Feature-Based** structure. This improves discoverability and modularity as the app grows.

**Current:**
- `data/food/AddFoodViewModel.kt`
- `pages/AddFood.kt`

**Suggested:**
- `features/food/AddFoodScreen.kt` (UI)
- `features/food/AddFoodViewModel.kt` (Logic)
- `features/food/AddFoodState.kt` (State/Events)

## 2. Introduce a Repository Layer
Decouple UI logic from the data source (Room) by introducing a Repository layer. This facilitates testing and future data source changes (e.g., adding a network API).

```kotlin
// features/food/data/FoodRepository.kt
class FoodRepository(private val foodDao: FoodDao) {
    fun getAllFoods(): Flow<List<Food>> = foodDao.getAll()
    suspend fun insertFood(food: Food) = foodDao.insert(food)
}
```

## 3. Implement Dependency Injection (Hilt)
Replace manual `ViewModelProvider.Factory` boilerplate with **Hilt**.

**Current:**
```kotlin
companion object {
    val Factory: ViewModelProvider.Factory = object : ViewModelProvider.Factory { ... }
}
```

**Suggested (with Hilt):**
```kotlin
@HiltViewModel
class AddFoodViewModel @Inject constructor(
    private val repository: FoodRepository
) : ViewModel() { ... }
```

## 4. Consolidate Navigation Logic
Keep `NavigationRoot.kt` focused on routing. Move `@Serializable` `NavKey` definitions to a dedicated `navigation` package or their respective feature packages.

## 5. Cleanup Redundant Files
Identified duplicate/redundant files like `AddFoodViewModel` in both `data.food` and `components.chars`. Consolidate these into a single, feature-specific location.

## 6. Centralize UI Components
Ensure the `components` directory contains only truly reusable, generic UI elements. Move feature-specific components into their respective feature packages.

## 7. Modernize Time Handling
Consistently leverage `java.time` APIs throughout the project (using API desugaring if necessary) instead of mixing with older `Calendar` or `Date` logic.

## Recommended Directory Structure Summary:
```
com.thisthatdc.calorytracker
├── core
│   ├── data (Database, Shared Repositories)
│   ├── ui (Theme, Shared Components)
│   └── util (Extensions, Time helpers)
├── features
│   ├── home
│   ├── food (AddFood, EditFood)
│   ├── settings
│   └── garmin
├── MainActivity.kt
└── NavigationRoot.kt
```

## Implementation Plan

### Phase 1: Foundation (DI & Data Layer)
1. **Add Hilt Dependencies**: Add necessary Hilt plugins and dependencies to `build.gradle.kts` (project and app levels).
2. **Create Data Layer**: Implement `FoodRepository` in `core/data` to wrap `FoodDao`.
3. **DI Setup**: Create a `HiltAndroidApp` class and update `AndroidManifest.xml`. Annotate `AppDatabase` and Provide it via a Hilt Module.

### Phase 2: Project Restructuring
1. **Directory Setup**: Create `core/` and `features/` directory structures.
2. **Move Theme**: Relocate `ui/theme` to `core/ui/theme`.
3. **Move Utils**: Relocate `util/Time.kt` to `core/util/Time.kt`.

### Phase 3: Incremental Feature Migration
1. **Food Feature**: 
   - Move all food-related screens and ViewModels to `features/food`.
   - Refactor ViewModels to use `@HiltViewModel` and inject `FoodRepository`.
   - Remove redundant ViewModels from `components/chars`.
2. **Home & Settings**:
   - Move `pages/Home.kt` and `pages/Settings.kt` to their respective `features/` packages.
   - Refactor for Hilt.

### Phase 4: Finalization
1. **Update Navigation**: Adjust `NavigationRoot.kt` to point to the new feature packages.
2. **Clean Up**: Remove empty directories and ensure all `java.time` usage is consistent using the new `core/util` helpers.
